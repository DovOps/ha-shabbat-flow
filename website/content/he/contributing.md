# מדריך מפתחים: סוכני קוד ופיתוח מבוסס מפרטים

Shabbat Flow מפותח בתהליך מבוסס מפרטים: דרישות, תוכנית יישום, משימות, ניתוח, מימוש ואימות. עדכנו דרישות פונקציונליות ולא־פונקציונליות יחד עם שינויי הקוד.

המאגר הציבורי מכיל דוגמאות כלליות בלבד. יש לשמור פרטי משפחה, מזהי התקנים אמיתיים, היסטוריית בית, סודות וצילומי התקנה פרטיים מחוץ למאגר. השתמשו בנתוני בדיקה בדיוניים ובמיתוג המקורי. אין לטעון לחסות HA או להעתיק עיצובים של שילובים אחרים ללא סקירה.

קראו את [הוראות התורמים](https://github.com/DovOps/ha-shabbat-flow/blob/main/AGENTS.md), [חוקת הפרויקט](https://github.com/DovOps/ha-shabbat-flow/blob/main/.specify/memory/constitution.md) ו[החלטות התלויות](reference/docs/dependencies.md). יש לחתום על תרומות באמצעות DCO עם `git commit -s`.

## מומלץ: פיתוח בעזרת סוכן קוד

הפרויקט מתוכנן ל**פיתוח מבוסס מפרטים בסיוע LLM או סוכן קוד**. הסוכן קורא דרישות, מציע שינוי ממוקד, מממש ומריץ בדיקות; המפתח סוקר את ההחלטות והתוצאה. גם תרומות ללא סוכן מתקבלות באותו תהליך.

**מתחילים בקובץ `AGENTS.md` בשורש המאגר.** זהו שער הכניסה של הסוכן לתהליך, לגבולות התרומה, לבדיקות ולתחזוקת המפרטים. אל תניחו שהכלי טען אותו: בקשו במפורש לקרוא אותו, את החוקה ואת המפרט הרלוונטי תחת `specs/`.

### מבקשה לשינוי שניתן לסקור

1. קראו את `AGENTS.md`, החוקה, החלטות התלויות והמפרט הרלוונטי.
2. הבהירו את ההתנהגות המבוקשת ועדכנו FR, NFR, תנאי קבלה ומגבלות לפני היישום.
3. עדכנו תוכנית ומשימות ובדקו תלויות ועקיבות דרישות בניתוח.
4. ממשו שינוי קטן שניתן לסקור, עם נתונים בדיוניים, תמיכה בעברית ובאנגלית ו־RTL בשינויי ממשק.
5. הריצו את בדיקות המאגר והבדיקות המתאימות לשינוי. תעדו ראיות והפרידו בין מימוש, התקנה ואימות חי.
6. עדכנו מצב דרישות ומפת דרכים. סקרו את ההבדלים וודאו שאין פרטי בית לפני commit חתום או push שאושרו. פריסה ושליטה בהתקנים דורשות אישור נפרד.

המאגר נעזר בתבניות ובסקריפטים של GitHub Spec Kit. אין בכך טענה שפקודות מיוחדות לסוכן מסוים מותקנות או נדרשות. ראו [תהליך ומקור Spec Kit](https://github.com/DovOps/ha-shabbat-flow/blob/main/docs/spec-kit.md).

### בקשת פתיחה להעתקה

```text
עבוד משורש המאגר. קרא את AGENTS.md, החוקה, החלטות התלויות
והמפרטים הקשורים לבקשה: [תיאור השינוי].
עדכן תחילה FR, NFR, תנאי קבלה, תוכנית ומשימות.
הצג החלטות פתוחות ואז ממש שינוי קטן שניתן לסקור.
השתמש בנתונים בדיוניים; אל תייבא פרטי בית או סודות.
שמור על תיעוד ותמיכה רב־לשונית, עם עברית ואנגלית כברירת מחדל.
הרץ בדיקות ודווח על ראיות ומגבלות שנותרו.
אל תפרוס, תפעיל התקנים או תבצע commit/push ללא אישורי.
```

פלט הסוכן הוא תרומה לסקירה, לא אישור או הוכחת נכונות. ההחלטות הנדרשות לתורם הבא צריכות להישמר במפרטים, ולא רק בהיסטוריית שיחה.

## שמירת האתר מעודכן

תוכן ההסבר והמדריכים נמצא ב־`website/src` וב־`website/content`. המקורות הטכניים נוצרים אוטומטית מ־`specs/` וממסמכים נבחרים תחת `docs/`. יש לערוך את המקורות, לא את הפלט שנוצר. גרסת השילוב נקראת ישירות מקובץ ה־manifest.

מתיקיית המאגר:

```sh
cd website
npm ci
npm run build
npm run check
npm run serve
```

התצוגה המקומית נמצאת ב־`http://localhost:3000/ha-shabbat-flow/`; עברית ב־`/ha-shabbat-flow/he/`. לפיתוח באנגלית עם רענון חי השתמשו ב־`npm start`, ולעברית ב־`npm start -- --locale he`. לאחר שינוי מפרטים מקוריים יש להריץ שוב הכנת תוכן.

בקשות מיזוג בונות את שתי השפות. לאחר הפעלת Pages, עדכונים ל־`main` מפרסמים את האתר דרך GitHub Actions. מדריך תחזוקת האתר במאגר מפרט את ההגדרה הראשונית.
