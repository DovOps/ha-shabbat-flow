# Analysis
Twilio SMS UI is installed and its service requires target, message and a configured from_number. The inspected adapter catches Twilio errors, so service completion is only submitted/unconfirmed. No provider package/source is adopted. Notifications are a separately opted-in outbound side effect, not device control. Report URLs contain a run ID but no credentials and rely on existing HA admin authentication. At-most-once dispatch trades possible lost notifications for avoiding duplicate billing/messages after uncertain failures.

Settings discovery adds no provider installation or mandatory third-party dependency. Core and feature requirements are distinct from optional capabilities. Jewish Calendar may be detected yet incomplete; each real plan still validates future coverage. Companion App registered notification action plus loaded provider indicates dispatch capability, not phone permission, remote connectivity or delivery. Both channels remain explicit opt-ins.

Reminders are a limited opt-in scheduler for preparation prompts, not scheduled study collection or automation execution. Calendar lookup is read-only. First candle of a continuous period avoids second/third-day prompts during issur. Missing or ambiguous status fails closed; same-day and two-minute grace avoid previous-evening reminders and restart catch-up floods. Draft presence does not suppress review prompts. An in-flight provider call cannot be recalled; cancellation applies to queued attempts. Persist-before-call is at-most-once, not exactly-once delivery.
