# Feature 018 — away defaults and scheduled lighting execution

Status: implemented, tested and deployed as an unarmed lighting pilot (0.20.0). Actual-device qualification and household activation remain pending. Installation never arms a run.

## Functional requirements
- GO-FR-001: Selecting Nobody home marks ordinary meals Away and afternoon hosting None for that observance segment, hides irrelevant meal controls and explains why. Selecting Home again requires fresh meal choices; do not restore hosting silently. Already-saved away drafts with unset meals must preview without meal prompts. Preserve dates, unrelated segments and existing observation snapshots. Conflicting room-use choices remain explicit review items.
- GO-FR-002: Add a separate Schedule and observe panel after a complete preview. Review server-compiled immutable plan, exact device IDs/names, dates, first/last action, included/excluded loads, qualification and ownership findings. Nothing is selected automatically. Approval and Schedule activation are distinct admin actions, bound to revision and digest with request idempotency. No control on Save, Preview, upgrade or calendar change.
- GO-FR-003: Initial live adapter is explicit binary On/Off for reviewed light/switch lighting roles only. Require per-device weekday On/Off verification attestation and notes bound to registry identity/provider before inclusion. Native HVAC, fans, outlets/appliances and unclassified loads remain excluded with visible reasons; no generic climate resume fallback. Preserve Feature 010 HVAC qualification gates.
- GO-FR-004: At each due action, read the current state first. Matching state records Already correct and sends no call. A known mismatch gets only its explicit On or Off command. Unknown/unavailable is not Off. No blanket startup On and no invented state before a device's first intended event. An opted-in preparation event may correct a missed manual setup light.
- GO-FR-005: Frozen armed runs start locally at their approved time without a browser. Pair activation with an observe run; export execution ledger alongside expected/observed evidence. Status identifies approved, armed, running, completed, disarmed and blocked records. Disarm leaves physical states unchanged and reports in-flight attempts.
- GO-FR-006: Review automation writers independently of the display forecast. Known overlapping/same-target writers block inclusion; dynamic/unknown writers require per-source/per-selected-load rationale of no access. Missing global source access blocks activation. Recheck fingerprints and mapping before dispatch; changes block affected execution. Never disable existing automations. External handoffs remain excluded from this pilot.
- GO-FR-007: Persist dispatch intent before service calls; separate acknowledgment from observed confirmation. Bounded concurrency, timeout, confirmation deadline and 120-second event grace. Missed/unavailable/uncertain resources block rather than replay stale transitions or fight external changes. Keep UTC timestamps and stable event IDs across restart and clock rollback.
- GO-FR-008: Restart recovery waits the configurable boot delay, evaluates current expected state and never replays a transition sequence. Optional periodic correction is limited to devices this run previously changed and confirmed, with configurable minimum 5-minute interval (default 30), maximum two corrections per load/run and no corrections after expiry, disarm, manual user override or a detected source/mapping change. Off by default for this live pilot. Detect ambiguous attempts; matching observation can satisfy without attribution, mismatches outside grace block. Document conservative behavior beyond grace.
- GO-FR-009: No run with entirely Away availability can arm. No new automatic final all-Off. Excluded devices remain visible and require explicit acknowledgment; an approval does not imply all planned HVAC or other loads will run. Require activation at least five minutes before preparation or the first included event, whichever is earlier.

## Nonfunctional requirements
- GO-NFR-001: Admin-only bounded APIs, strict request fields, no arbitrary service payloads, labels or area targets. Physical commands use explicit frozen entity IDs and per-run contexts. Durable lock-serialized approval/reservations; corruption or save failure disables dispatch. Unload and deployment do not activate drafts.
- GO-NFR-002: EN/HE parity, dates with timezone, keyboard-accessible review, explicit text outcomes and progress. Household status and reports distinguish observation from armed control. No private fixtures or production device tests during development/deployment.
- GO-NFR-003: Cover away/multiday migration, no-op matching state, due/missed actions, auth, duplicate activation, concurrent overlapping ownership, disarm races, unavailable state, storage/crash/restart, source drift, unknown-source attestations, and observation linking with HA service spies on both supported versions. Native device tests remain the owner's prerequisite, not inferred from simulated tests.
- GO-NFR-004: Retain bounded 20-run/90-day private records; never prune active runs. One-second event scheduler; maximum four service calls concurrently, 10-second acknowledgment deadline and 30-second confirmation. Do not claim target latency measured on production hardware. No new third-party dependency. Polling/status lists omit full ledgers; retrieve detailed execution evidence only on export or report request.

## Scope relative to Feature 010
This is a conservative lighting pilot. Full HVAC verification adapters, live external handoffs, automatic retries, large-workload latency qualification and per-unit live acceptance remain explicitly open. The runtime does not claim these broader requirements complete. Default grace/deadline/no-blanket-shutoff policies remain unchanged. Optional bounded correction refines EX-FR-032 without treating absence of user ID as physical-switch attribution.
