# Feature 015 — guided planning, reports and period reviews

Status: implemented and locally tested in 0.18.0; deployment evidence recorded separately. Extends 004/010/011/013/014; no live device control or new dependency.

## Functional requirements
- UX-FR-001: Add Reports beside Settings across the HA UI. List retained plan observations and climate studies, newest first, with dates, status, type, feedback state, filters and direct HTML/PDF/JSON access. Empty/loading/error states must explain the next action.
- UX-FR-002: Put primary planner commands in a compact sticky top bar: Preview, save browser draft, observe setup and exports. Keep recovery/destructive draft commands in a labeled More menu. Icons supplement visible labels; no icon-only critical command. Show Plan → Preview → Save/Observe → Review guidance and readiness; edits invalidate previews and exports. Explain that saving a browser draft does not schedule an observation.
- UX-FR-003: Keep optional activities/advanced controls collapsed; retain basic home, rooms and meals as the main flow. Group observation controls into start setup versus existing-run management, with links to Reports rather than a large permanent historical-report panel at the bottom.
- RP-FR-001: Every retained observation produces a deterministic performance summary, automatically available when complete, partial while running/stopped. No report is invented for a period without a started observation. No background PDF generation, unsolicited notification, or automatic study activation.
- RP-FR-002: Separate observed state agreement from actuation success, comfort and occupancy. Show assessed matched/mismatched minutes, unknown/unplanned time, event outcomes, collection warnings and per-room breakdown; explain denominators. Climate-only studies have no plan-agreement score. Existing automations remain separately attributed. No causal or execution-success claim in observe mode.
- RP-FR-003: Allow authenticated administrator period review with exact run/plan identity: overall/lighting/climate 1–5 ratings, unanswered and N/A, ordinary/exceptional/uncertain period, what worked, what differed, and one proposed next change. Classify the change as settings, app improvement or uncertain, with proposed/applied-to-future-settings/deferred/dismissed state. Save explicitly with optimistic revision checks; never edit a frozen plan or apply/activate a change.
- RP-FR-004: Include review and performance in HTML/PDF/full JSON. Offer a separate review-bundle download for user-directed analysis. Clearly label household text private and require manual generalization before use in public specifications/issues; never publish automatically. Provide clear-review action. No identity fields.
- RP-FR-005: Retention inherits observation storage: max 20 runs, 90 days for terminal runs. Feedback is bounded, stored inside its run and removed with it. Clear review removes review text/ratings while advancing revision. Review edits preserve up to 10 prior versions until cleared; display saved revision/update time. Explain retention and export-before-expiry.

## Nonfunctional requirements
- UX-NFR-001: EN/HE parity, RTL, keyboard navigation, labeled icons, visible focus, wrapping mobile toolbar without covering controls. PDF excludes navigation/toolbars/forms and uses the shared report renderer.
- RP-NFR-001: Compact report index without inventory or full histories; load a full run only on opening/export. No long-running computation or repeated full reports during typing; bounded forms/history and existing 60-second observer work remain unchanged.
- RP-NFR-002: Atomic durable writes and optimistic locking for reviews; validate rating/enums/text/IDs, reject stale edits, handle storage failures without reporting success. Authenticate/admin-check every API operation. Export excludes actor/request IDs. No services/devices/automations mutated by reports/review.
- RP-NFR-003: Additive compatibility: old runs without reviews remain valid. Report calculation never changes snapshots or compiler output. Test unknown-only and empty coverage, climate-study score suppression, partial periods, aliases, stale/clear/reload and zero service calls. Fictional fixtures only.

## Boundaries
This implements an owner review and explicit improvement tracking. Multi-person questionnaires, automatic comparable-cohort trends, AI suggestions, automatic requirement publication and accepted proposal application remain Feature 004 future work. Settings marked applied are user reports, not proof that an app change occurred. Full live execution metrics await Feature 010.
